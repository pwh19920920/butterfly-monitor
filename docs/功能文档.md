## 1. 系统功能概览


| 功能模块 | 说明 |
|---|---|
| 监控任务管理 | 配置数据采集任务（数据库 SQL / URL HTTP / 外部推送），设定采集周期与指令 |
| 数据源管理 | 管理被监控数据源（Mongo / Mysql 协议族 / PostgreSQL / ClickHouse / Prometheus / VictoriaMetrics / TDengine / OpenSearch / Elasticsearch 只读），密码加密存储 |
| 监控分组 | 树形依赖分组，用于关联预警链路 |
| 监控面板 | 对接 Grafana 自动创建/管理监控大盘与 panel |
| 告警规则 | 为任务配置阈值规则（百分比/绝对值/样本差值，5 种比较，Or/And 组合，生效时段，分级） |
| 告警配置 | 全局 KV 配置（报警间隔、首次延迟、通知模板、样本生成参数） |
| 告警分组 | 管理告警接收人分组与成员 |
| 告警通道 | 管理邮件 / 企业微信通知通道，支持测试发送 |
| 告警事件 | 告警事件查询、处理（误报标定）、完成 |
| 首页统计 | 任务/事件/面板/数据源数量聚合 |
| 健康检查 | 探活接口 |

### 1.0 技术栈

| 层 | 技术 |
|---|---|
| 后端 | Go 1.26 + Gin（butterfly）+ GORM + MySQL（平台元库），DDD 分层 |
| 前端 | React 19 + Umi Max 4 + Ant Design Pro |
| 时序存储 | 可插拔：VictoriaMetrics（默认）/ TDengine（`timeseries.backend`） |
| 可视化 | Grafana（任务保存时自动同步 dashboard/panel） |
| 调度 | XXL-JOB（dataCollect / dataSampling / alertCheck / eventCheck） |
| 通知 | 邮件 / 企业微信 |
| 鉴权 | JWT + 菜单权限 |
| 被监控数据源 | **独立 handler**：MongoDB、PostgreSQL、ClickHouse、TDengine（只读 REST SQL）；**Prometheus / VictoriaMetrics**（只读 PromQL/MetricsQL，共用 handler）；**OpenSearch / Elasticsearch**（只读查询，共用 handler）；**MySQL 协议族（复用）**：Mysql、MariaDB、TiDB、OceanBase（MySQL 模式）、Doris、StarRocks |

### 1.1 核心业务链路

```
指标采集(dataCollect) → 样本生成(dataSampling) → 规则检测(alertCheck) → 事件通知(eventCheck)
```

四个定时任务由 XXL-JOB 调度，cron 在 admin 端配置：

- **dataCollect**：定时从数据源采集指标写入时序库，同时写未来 8 天同时刻样本原料点。
- **dataSampling**：按窗口生成样本（去除最大值最小值取平均值），写入平滑基线指标 `{taskKey}_sample`。
- **alertCheck**：比对实时均值与平滑基线均值，命中并持续达阈值生成告警事件。
- **eventCheck**：到期事件经模板渲染，通过邮件/企业微信外发。

### 1.2 告警生命周期

```
规则命中(异常持续) → 生成事件(Pending) → 到期外发 → 人工处理 → 完成
                         ↑ 失败/误报可标 Ignore
```

- **Pending**（待处理）：事件已生成，等待 `NextAlertTime` 到期外发。
- **Processing**（处理中）：人工介入处理，暂停检测。
- **Complete**（已完成）：处理完成，规则恢复可检。
- **Ignore**（已忽略）：误报标定，不外发。

### 2.5 告警规则（随任务管理）

告警规则 `MonitorTaskAlert` 与任务 `MonitorTask` 一对一，通过 `/api/monitor/task` 的 create/modify 一并管理，无独立路由。规则参数 `Params` 是 JSON：

```json
[{
  "relation": 1,                              // 1=组间Or, 2=组间And
  "effectTimes": ["00:00:00", "23:59:59"],     // 生效时间段
  "rules": [
    { "valueType": 1, "value": 10, "compareType": 1 }  // 比较值类型, 阈值, 比较方式
  ],
  "level": 0                                   // 事件等级，nil默认Critical
}]
```

## 3. 功能模块详解

### 3.1 监控任务

监控任务是系统的核心实体，一条任务定义了"采集什么、怎么采集、多久采集、告警规则是什么"。

**任务类型**（`TaskType`）：

| 值 | 类型 | 说明 |
|---|---|---|
| 1 | Database（数据库） | `Command` 是 SQL，`ExecParams` 含 `databaseId`，从连接池取对应数据源执行 |
| 2 | URL | `Command` 是 URL 模板，`ExecParams` 含 `resultFieldPath`，HTTP GET 探测取 JSON 路径值 |

**关键字段**：
- `TaskKey`：任务标识，**同时作为时序库指标名**，需全局唯一。
- `TimeSpan`：窗口前进间隔（秒），决定采集周期。
- `StepSpan`：查询区间宽度（秒）。
- `Command`：执行指令（URL 或 SQL 模板，支持 `text/template` + `sprig` 渲染，可引用 `endTime`/`beginTime`/`startTime`/`startTimeMilli`/`endTimeMilli`/`beginTimeMilli`）。
- `ExecParams`：执行参数 JSON。
- `TaskStatus`/`AlertStatus`/`Sampled`：任务开关/告警开关/样本展示开关。
- `MonitorGroup`：依赖分组（逗号分隔 groupId，关联预警用）。
- `Labels`：标签 JSON（预留扩展字段，当前运行链路不消费）。

**采集周期机制**：分片查询条件 `date_add(now(), interval -time_span second) >= pre_execute_time`，即距上次执行已超过一个 `TimeSpan` 才到下次采集点。`dataCollect` Job 模式只采集最近一个窗口。

**样本机制**：采集时**无条件**同步写未来 8 天同时刻样本原料点（指标 `{taskKey}_sampling`，标签 `day=1..8`），`dataSampling` 按窗口去除最大最小后取均值、生成平滑基线写入新指标 `{taskKey}_sample`，`alertCheck` 用 `avg({taskKey}_sample)` 与 `avg({taskKey})` 实时均值做对比。**`Sampled` 开关只控制 Grafana 面板是否展示样本对比线，不影响采集与样本生成**——样本数据始终采集与生成，`Sampled` 决定的是"是否在面板上展示"。

### 3.2 数据源

数据源是被监控的数据库实例配置，密码密文存储（DES-CBC + 随机 8 位盐）。

> **操作手册（连接字段 / Command 示例 / FAQ）**：[数据源添加说明.md](./数据源添加说明.md)

**数据源类型**（`DataSourceType`，实体 `monitor_database.go` / 前端 `DatabaseTypeEnum`）：

| 值 | 类型 | handler | `task.Command` 语义 | 说明 |
|---|---|---|---|---|
| 1 | Mongo | `DatabaseMongoHandler` | Extended JSON 聚合管道 | 独立实现 |
| 2 | Mysql | `DatabaseMysqlHandler` | SQL | 独立实现 |
| 3 | PostgreSQL | `DatabasePostgresHandler` | SQL | 独立实现；DSN 为 `postgres://` URL |
| 4 | MariaDB | `DatabaseMysqlHandler` | SQL | MySQL 协议兼容，复用 |
| 5 | TiDB | `DatabaseMysqlHandler` | SQL | MySQL 协议兼容，复用 |
| 6 | OceanBase | `DatabaseMysqlHandler` | SQL | **仅 MySQL 模式**；Oracle 模式不支持 |
| 7 | Doris | `DatabaseMysqlHandler` | SQL | MySQL 协议兼容，复用（连 FE/MySQL 端口） |
| 8 | StarRocks | `DatabaseMysqlHandler` | SQL | MySQL 协议兼容，复用（连 FE/MySQL 端口） |
| 9 | ClickHouse | `DatabaseClickHouseHandler` | SQL | 独立方言；原生协议端口常见 9000 |
| 10 | Prometheus | `DatabasePrometheusHandler` | PromQL | **只读**；`GET /api/v1/query`；默认端口 9090 |
| 11 | OpenSearch | `DatabaseOpenSearchHandler` | `_search` JSON / `_count` / SQL | **只读**；默认 9200 |
| 12 | Elasticsearch | `DatabaseOpenSearchHandler`（复用） | 同 OpenSearch | **只读**；查询 API 兼容，共用实现 |
| 13 | VictoriaMetrics | `DatabasePrometheusHandler`（复用） | MetricsQL/PromQL | **只读**；默认端口 **8428** |
| 14 | TDengine | `DatabaseTDengineHandler` | REST SQL | **只读**；`POST /rest/sql`；默认端口 **6041** |

**实现分组**：

1. **MySQL 协议族**（2/4/5/6/7/8）：共用 `DatabaseMysqlHandler` + `go-sql-driver/mysql`。DSN：`user:pass@tcp(host:port)/db?params`，默认 params=`charset=utf8mb4&parseTime=True&loc=Local`。只读防御：`validateReadOnlySQL` + `SET SESSION TRANSACTION READ ONLY`。
2. **MongoDB**（1）：`DatabaseMongoHandler`，URI 形如 `mongodb://[user:pass@]host[:port]/db[?params]`，Command 为聚合管道。
3. **PostgreSQL**（3）：`DatabasePostgresHandler` + `gorm.io/driver/postgres`（pgx）。DSN：`postgres://user:pass@host:port/db?sslmode=disable`（`Url` 无端口默认 5432）。只读防御：`SET default_transaction_read_only = on/off`。
4. **ClickHouse**（9）：`DatabaseClickHouseHandler` + `gorm.io/driver/clickhouse`（clickhouse-go v2）。DSN：`clickhouse://user:pass@host:port/db?dial_timeout=10s&readonly=1`（`Url` 无端口默认 **9000** 原生协议）。只读：连接级 `readonly=1` + 静态 SQL 校验；单值查询对 UInt64/Decimal 做数值转换。
5. **Prometheus / VictoriaMetrics**（10/13）：共用 `DatabasePrometheusHandler`，**仅 HTTP 查询、零写入**。`url=host:port`（Prometheus 默认 9090，VM 默认 **8428**），`params` 可选 `scheme=https`、`path_prefix`、`timeout=30s`。`Command` 为完整 PromQL/MetricsQL；单值取 vector/scalar 第一个点，多行聚合每个 series 一行（labels + `value`）。探活 `/-/healthy`（失败可降级 buildinfo）。
6. **OpenSearch / Elasticsearch**（11/12）：共用 `DatabaseOpenSearchHandler`，**仅 HTTP 查询、零写入**。`url=host:port`（默认 **9200**），`database`=默认 index；`params.api`=`search`（默认）/`count`/`sql`。`Command`：search 为完整 `_search` JSON；count 可为空 body；sql 优先 `/_plugins/_sql`，失败回退 ES `/_sql`。单值取 metric 聚合 value 或 `hits.total`；多行展开 terms buckets（`key`/`doc_count`/`value`）。
7. **TDengine**（14）：`DatabaseTDengineHandler`，**仅 REST SQL 查询、零写入**。`url=host:port`（默认 **6041** taosAdapter），`database`=业务库；`params` 可选 `scheme`、`timeout`。`Command` 为只读 SQL；单值取首行首个数值列，多行按 `column_meta` 映射。与平台 `timeseries.backend=tdengine` 是不同角色。

**连接字段约定**（`t_monitor_database`）：

| 字段 | 含义 |
|---|---|
| `url` | 地址。MySQL 族 / PG / ClickHouse / Prometheus / VM / TDengine / OpenSearch / ES：`host:port`；Mongo：host 或 `host:port` |
| `database` | 库名（Mongo 为 database name；**Prometheus/VM 可留空**；**TDengine 为业务库**；**OpenSearch/ES 为默认 index**） |
| `username` / `password` | 账号；密码落库前 DES-CBC + 随机盐加密（Prometheus/VM/OpenSearch/ES Basic Auth 可选；TDengine 默认 root） |
| `params` | 附加连接参数。MySQL 族 = DSN `?` 后；PG / ClickHouse = URL query；Mongo = URI query；Prometheus/VM/TDengine/OpenSearch/ES = `scheme`/`timeout` 等（Prometheus/VM 另有 `path_prefix`；OpenSearch/ES 另有 `api`） |
| `type` | 上表枚举值 |

**连接池动态注册**：`CommonMapApplication` 启动后台 goroutine 每分钟增量扫描 `t_monitor_database`，按 `type` 取 handler 调 `NewInstance` 建连，成功的放进 `databaseMap[id]`，注入 `CommandDataBaseHandler`。新增/修改的数据源最多 1 分钟后生效；修改/删除会先 `RemoveDatabaseConn` 关闭旧连接。

### 3.3 监控分组

树形依赖分组，用于"关联预警"链路。`Route` 字段形如 `/1/2/3/`，`Parent` 为上级 id。修改分组时级联更新所有子节点 Route。

**关联预警**：`eventCheck` 的 `getEventRelationParams` 按 `task.MonitorGroup` 取 `MonitorGroup.Route`，`LastIndex(route, "/")` 去掉最后一节，`Split(route[0:lastIndex], "/")` 得上游 groupId 列表，从各组 pending events 取关联 task name，串成 "A -> B -> C" 链路关系名放进通知模板。

### 3.4 监控面板

对接 Grafana，自动创建/管理大盘与 panel。

- **创建面板**：调 `grafanaHandler.CreateDashboard(name)`，从响应回填 `Url/Slug/Uid/BoardId`。
- **panel 标识**：以 `panel.Description == taskKey` 为锚点做增删改。每个 task 对应一个 timeseries panel；Grafana 数据源类型由 `timeseries.backend` 决定（VM 时为 Prometheus/MetricsQL，TDengine 时按其方言），target A 查实时指标 `{taskKey}`，`Sampled=Open` 时加 target B 查平滑基线 `{taskKey}_sample` 做样本对比。
- **三段式同步**：修改任务时计算 dashboard 新增/删除/交集三集合，`ModifyDashBoardPanel` 同步 Grafana：交集只改 title、删除匹配 panel、新增 panel。
- **自动布局**：`sortPanels` 3 列网格（每格 `8×8`）。
- **排序**：`/api/monitor/dashboard/taskSort` 批量改排序后，`ReSortDashboard` 按 taskId 顺序重建 panels。

### 3.5 告警规则

每个任务一条告警规则 `MonitorTaskAlert`，核心是 `Params`（规则 JSON）。

**规则结构**：
- 组间关系 `Relation`：1=Or（一组命中即整体命中）、2=And（全命中才命中）。
- 组内规则 `Rules`：每条含 `ValueType`（比较值类型）、`Value`（阈值）、`CompareType`（比较方式）。
- 生效时段 `EffectTimes`：`[startHH:mm:ss, endHH:mm:ss]`，不在时段内跳过该组。
- 事件等级 `Level`：nil 默认 Critical。

**三种比较值类型**：

| ValueType | 值 | 含义 |
|---|---|---|
| Percent | 1 | 样本百分比：`(real - sample) * 100 / sample` |
| AbsoluteValue | 2 | 实时数值比较：不依赖样本，直接比较实时值 |
| Value | 3 | 样本差值：`real - sample` |

**五种比较方式**：

| CompareType | 值 | 中文 | 差值模式 | 实时数值模式 |
|---|---|---|---|---|
| Gt | 1 | 超出 | `diff > value` | `real > value` |
| Lt | 2 | 低于 | `diff < -value` | `real < value` |
| Eq | 3 | 等于 | `diff == value` | `real == value` |
| Egt | 4 | 超出或等于 | `diff >= value` | `real >= value` |
| Elt | 5 | 低于或等于 | `diff <= -value` | `real <= value` |

**告警等级**（`MonitorAlertCheckParamsLevelType`）：

| 常量 | 值 | 中文(loadLevel) | 英文(transferLevel) |
|---|---|---|---|
| Normal | -1 | 低级（default） | Low |
| Critical | 0 | 严重 | Critical |
| High | 1 | 高级 | High |
| Medium | 2 | 中级 | Medium |
| Low | 3 | 低级 | Low |

**规则命中流程**（`alertCheck`）：
1. 时间倒退窗口 `[now-2*TimeSpan, now-TimeSpan)` 查平滑基线均值 `avg({taskKey}_sample)` 与实时均值 `avg({taskKey})`。
2. 实时值缺失 / 依赖样本但样本缺失 → 保守标 Pending。
3. 三个分支：
   - **未命中** → 恢复正常（`ModifyForNormal`），pending events 标 Ignore（不向外部平台推送）。
   - **命中但未超 Duration** → 置 Pending（`ModifyByPending`），冻结 `FirstFlagTime` 作持续起点。
   - **命中且超 Duration** → 置 Firing（`ModifyByFiring`），创建/更新事件（`DealStatus=Pending`、`NextAlertTime=now+FirstDelay`、`EventLevel=level`）。

**Alert 状态机**：

| AlertStatus | 值 | 含义 |
|---|---|---|
| Normal | 1 | 正常 |
| Pending | 2 | 出现异常（待观察，等待 Duration） |
| Firing | 3 | 达到报警条件（正在报警） |

### 3.6 告警配置

通用 KV 配置表，运行期装配成 `AlertConfObject`。关键配置项见 §2.6。

**配置动态装配**：`Cover2AlertConf` 用独立 viper 实例，设默认值（`alert.firstDelay=60`、`alert.alertSpan=300`），再以 `alert.<ConfKey>=<ConfVal>` 逐条覆盖。

**NextAlertTime 握手机制**：
- `alertCheck` 建事件时 `NextAlertTime = now + FirstDelay`（首次延迟 60s）。
- `eventCheck` 发送成功后按 `AlertSpan * 2^min(AlertCount,5)` 翻倍退避（上限 1800s）写 `NextAlertTime`。
- `FindEventJob` 扫描条件 `now() >= next_alert_time`，实现报警频次控制。

### 3.7 告警分组

管理告警接收人分组与成员（多对多中间表 `t_alert_group_user`）。告警时按 `alert.AlertGroups` 解析出分组，再按分组取用户列表，最后按通道发送。

### 3.8 告警通道

| 通道 | Handler | 参数 | 发送方式 |
|---|---|---|---|
| 邮件 | `ChannelEmailHandler` | `{Host, Port, SSL, Username, Password}` | SMTP/SMTPS，主题"报警提醒"，纯文本正文 |
| 企业微信 | `ChannelWechatHandler` | `{Addr}`（机器人 webhook） | POST `{"msgtype":"markdown","markdown":{"content": message}}` |

通道 handler 不做模板渲染，`message` 由 `eventCheck` 渲染后传入。模板优先级：通道自身 Template → `template.<Handler>` 配置 → 全局 `template`。

### 3.9 告警事件

事件状态机（`DealStatus`）：

| 值 | 状态 | 说明 |
|---|---|---|
| 1 | Pending（待处理） | 已生成，等待到期外发 |
| 2 | Processing（处理中） | 人工介入，暂停检测 |
| 3 | Complete（已完成） | 处理完成，规则恢复可检 |
| 4 | Ignore（已忽略） | 误报标定 |

**事件处理闭环**：
- `DealEvent`（处理）：余者标误报 → 当前事件置 Processing → 规则 DealStatus=Processing。
- `CompleteEvent`（完成）：事件 Complete → 规则恢复 Normal。
- `IgnoreEvent`（忽略）：仅 Pending 可忽略；该 alert 无剩余 Pending 时规则回 Normal。
- 自动恢复：`alertCheck` 未命中时 `ModifyForNormal`，Pending 事件标 Ignore，**不**推外部平台。

### 3.10 首页统计

`/api/monitor/homeCount` 聚合返回 TaskCount / EventCount / DashboardCount / DatabaseCount，免登录。

## 5. 定时任务

四个定时任务由 XXL-JOB 调度，cron 在 admin 端配置，不在代码中。

| 任务名 | 功能 | 分片 | 关键参数 |
|---|---|---|---|
| `dataCollect` | 采集指标写时序库 + 写未来 8 天样本原料点 | `mod(id,Total)=Index` | `TimeSpan`/`StepSpan`/`TaskType`/`Command`/`ExecParams`/`CollectMaxSecond` |
| `dataSampling` | 按窗口生成平滑基线 `{taskKey}_sample` | 分片 + `id>lastId` 游标分页 | `SimplePageSize`(50)/`SimpleMaxSecond`(600s) |
| `alertCheck` | 比对实时均值与平滑基线均值，命中生成事件 | `mod(id,Total)=Index`（按 alert.id） | `Duration`/`Params`/`FirstDelay`(60s) |
| `eventCheck` | 到期事件模板渲染，经邮件/企微外发 | 不分片，全量扫描到期事件 | `AlertSpan`(300s)/`Template` |

**分片参数** `BroadcastIndex`/`BroadcastTotal` 由 XXL-JOB 调度中心下发，支持多 executor 实例水平扩展，同一任务按 `mod(id, Total)` 哈希到不同分片，避免重复执行。

## 6. 外部系统集成

### 6.1 Grafana

- 地址：`grafana.addr`（各 profile 不同）。
- 集成点：监控任务增删改同步操作 Grafana 面板与 panel；面板查询时 Url 前拼 `Grafana.Addr`。
- panel 查询：Grafana 数据源类型与表达式由 `MetricQueryDialect`（与 `timeseries.backend` 同一实现）决定。实时点指标=`{taskKey}`；样本对比线（`Sampled=Open` 时）查平滑基线指标 `{taskKey}_sample`。

### 6.2 XXL-JOB

- 地址：`xxl.serverAddr`。
- 执行器：取本机非回环 IPv4 作为 ExecutorIp，端口与 gin `serverAddr` 一致，RegistryKey=`server.serverName`。
- 注册路由：`POST /run`、`POST /kill`、`POST /log`。

### 6.3 数据源（被监控）

类型与字段约定见 [3.2 数据源](#32-数据源)。技术实现摘要：

- **MySQL 协议族**（type 2/4/5/6/7/8）：gorm + `go-sql-driver/mysql`，连接池 idle10/open100/life3600s，共用 `DatabaseMysqlHandler`；只读校验 + `SET SESSION TRANSACTION READ ONLY`。
- **MongoDB**（type 1）：mongo-driver v2，`SetMaxPoolSize(5)`，聚合管道；自动 `$limit` 防 OOM。
- **PostgreSQL**（type 3）：gorm + `gorm.io/driver/postgres`（pgx），连接池同上；DSN 为 `postgres://` URL；会话级 `default_transaction_read_only` 做只读防御。
- **ClickHouse**（type 9）：gorm + `gorm.io/driver/clickhouse`（clickhouse-go v2 原生协议），连接池 idle5/open50/life3600s；DSN 为 `clickhouse://` URL，默认 `readonly=1`；单值对 UInt64 等做数值转换。
- **Prometheus / VictoriaMetrics**（type 10/13）：纯 HTTP 只读客户端（无 SQL 驱动）；`GET /api/v1/query` 即时查询；**不对对方做任何写入**；采集结果仍写入平台自身时序库。VM 默认端口 8428。
- **TDengine**（type 14）：纯 HTTP 只读 REST SQL（`/rest/sql`）；**不建表、不 INSERT**；采集结果写入平台自身时序库。
- **OpenSearch / Elasticsearch**（type 11/12）：纯 HTTP 只读，共用 handler；`_search` / `_count` / SQL；**不 bulk/index 写文档**。
- 修改/删除数据源后 `RemoveDatabaseConn` 关闭旧连接，由每分钟刷新协程按新配置重建。

## 7. 使用流程示例

### 7.1 新增一个数据库监控任务

1. **数据源管理**：`POST /api/monitor/database` 创建数据源（选类型：Mysql 协议族 / Mongo / PostgreSQL，填库名/账号/密码/地址），系统按类型 `TestConnect` 验证连通性并加密密码。
2. **监控分组**（可选）：`POST /api/monitor/group` 创建依赖分组（树形），用于关联预警。
3. **监控面板**：`POST /api/monitor/dashboard` 创建 Grafana 面板。
4. **创建任务**：`POST /api/monitor/task`，填 `TaskKey`（唯一）、`TaskName`、`TimeSpan`/`StepSpan`、`Command`（SQL）、`TaskType=1`、`ExecParams={"databaseId": <id>}`、关联 dashboardIds、`MonitorGroup`、告警规则 `Params`。系统校验 TaskKey 唯一、在 Grafana 加 panel、事务保存。
5. 启用任务：`PUT /api/monitor/task/taskStatus/:id/1` 开启；`PUT /api/monitor/task/alertStatus/:id/1` 开启告警；`PUT /api/monitor/task/sampled/:id/1` 开启样本对比线展示（不影响采集与生成，仅控制 Grafana 面板是否叠加样本曲线）。
6. XXL-JOB admin 配置 `dataCollect`/`dataSampling`/`alertCheck`/`eventCheck` 四个任务的 cron 与分片。

### 7.2 配置告警通知

1. **告警通道**：`POST /api/alert/channel` 创建邮件/企业微信通道（填 Host/Port/SSL/Username/Password 或 webhook Addr），系统测试发送验证。
2. **告警分组**：`POST /api/alert/group` 创建分组并绑定用户（用户来自 `t_sys_user`）。
3. **告警配置**：`POST /api/alert/conf` 配置 `alertSpan`/`firstDelay`/`template` 等。
4. 创建/修改任务时在告警规则中填 `AlertGroups`（逗号分隔 group id）和 `AlertChannels`（逗号分隔 channel id）。

### 7.3 处理告警事件

1. 查询事件：`GET /api/monitor/task/event`。
2. 处理（人工介入）：`POST /api/monitor/task/event/deal/:id`，系统把同 task 其余 pending events 标为误报，当前事件置 Processing。
3. 完成：`POST /api/monitor/task/event/complete/:id`，事件置 Complete，规则恢复可检。
4. 忽略：`POST /api/monitor/task/event/ignore/:id`，仅 Pending 可忽略。

## 8. 常见问题

**Q：新增数据源后任务多久能用到？**
A：最多 1 分钟。后台 goroutine 每分钟增量扫描 `t_monitor_database` 建连注入连接池。在此之前 DB 类型任务执行会报 `dbMap is not contain <id>`。修改数据源（改密/改地址/改类型）后会先摘掉旧连接，同样由该刷新协程重建。

**Q：OceanBase / Doris / StarRocks / TiDB 怎么配？**
A：前端选对应类型即可，底层复用 MySQL handler。`url` 填 `host:port`（Doris/StarRocks 填 FE 的 MySQL 协议端口，常见 9030），`params` 与 Mysql 相同。**OceanBase 仅支持 MySQL 模式**，Oracle 模式请勿选用。

**Q：PostgreSQL 的 url / params 怎么填？**
A：`url` 填 `host:port`（无端口默认 5432）；`params` 填 libpq 风格查询串，如 `sslmode=disable` 或 `sslmode=require TimeZone=Asia/Shanghai`（空格会规范成 `&`）。留空默认 `sslmode=disable`。

**Q：ClickHouse 的 url / params 怎么填？**
A：`url` 填 `host:port`，**默认端口 9000（原生协议）**，不是 HTTP 8123。`params` 如 `dial_timeout=10s&readonly=1`；留空即该默认。若走 HTTP 协议需在 params 中按 clickhouse-go 文档显式配置，默认实现按原生协议。

**Q：Prometheus / VictoriaMetrics 数据源会写指标吗？**
A：**不会。** 仅调用对方的查询 API（`/api/v1/query`），把结果采到本平台时序库，再走基线/告警。对方只被读。

**Q：Prometheus / VictoriaMetrics 任务 Command 怎么写？**
A：写完整 PromQL/MetricsQL。单值示例：`sum(rate(http_requests_total{job="api"}[1m]))`。分组聚合示例：`sum by (code) (rate(http_requests_total{job="api"}[1m]))`，多行的 label 列可选 `code`，值列选 `value`。Prometheus 默认端口 9090，VictoriaMetrics 默认 **8428**；经 Ingress 时 `params` 加 `path_prefix=...` 或 `scheme=https`。

**Q：TDengine 数据源怎么配？会写对方吗？**
A：**不会写。** type=14，`url` 默认 **6041**（taosAdapter），`database` 填业务库；`Command` 写只读 SQL（`SELECT`/`SHOW`）。与平台 `timeseries.backend=tdengine` 是不同角色（后者是采集结果写入目标）。

**Q：OpenSearch / Elasticsearch 怎么配？会写索引吗？**
A：**不会写。** 类型 11/12 共用实现，只调 `_search`/`_count`/SQL。`url` 默认 **9200**；`database` 填默认 index（可空则走集群级路径）；`params.api=search|count|sql`（默认 search）。

- search 单值 Command 示例：`{"size":0,"query":{"match_all":{}},"aggs":{"c":{"value_count":{"field":"_id"}}}}`
- count：Command 可空，或带 query JSON
- sql：`SELECT count(*) FROM my-index`（OS 走 `/_plugins/_sql`，ES 回退 `/_sql`）
- 分组：terms agg 会展开为 `key` / `doc_count` / `value` 多行

**Q：告警为什么不外发？**
A：检查几项：
1. 事件是否到期：`FindEventJob` 条件 `now() >= next_alert_time`，未到期不外发。
2. 通道是否配置且测试通过：`AlertChannels` 是否填了有效 channel id。
3. 分组是否有成员：非纯 Webhook 时 `AlertGroups` 对应分组下是否有用户。
4. 任务/告警开关是否开启：`TaskStatus`/`AlertStatus` 是否为 open。

**Q：告警多久发一次？**
A：首次 `alertCheck` 建事件后 `NextAlertTime = now + FirstDelay`（默认 60s）；`eventCheck` 发送成功后按 `AlertSpan * 2^min(AlertCount,5)` 翻倍（默认基数 300s，上限 1800s）。可在 `t_alert_conf` 调整。

**Q：指标恢复正常后会怎样？**
A：`alertCheck` 未命中时 `ModifyForNormal`：规则回 Normal，Pending 事件标 Ignore。**不会**向外部平台推送 resolved；本系统外发仅依赖邮件/企微通道。

**Q：样本基线是什么？**
A：采集时同步写未来 8 天同时刻的样本原料点（`{taskKey}_sampling`，标签 `day=1..8`），`dataSampling` 按窗口聚合生成平滑基线写入 `{taskKey}_sample`。`alertCheck` 用样本均值与实时均值比对。样本原料**始终采集**，`Sampled` 开关只控制 Grafana 面板是否展示样本对比线。

**Q：`Sampled`（样本展示开关）开了/关了有什么影响？**
A：`Sampled=Open` 时 Grafana 面板叠加样本对比线；`Sampled=Close` 时不展示。**无论开关如何，样本原料都会被采集、平滑基线都会生成**——开关只影响面板展示。

**Q：多实例部署如何避免重复执行？**
A：定时任务按 `mod(id, shardTotal) = shardIndex` 分片，分片参数由 XXL-JOB 下发。`eventCheck` 不分片，建议单机或轮询路由。

**Q：TaskKey 有什么用？**
A：`TaskKey` 是任务唯一标识，**同时作为时序库指标名**（实时点指标=`{taskKey}`，样本原料指标=`{taskKey}_sampling`，平滑基线指标=`{taskKey}_sample`），也是 Grafana panel 的 `Description` 锚点。修改时原则上不改 TaskKey。
